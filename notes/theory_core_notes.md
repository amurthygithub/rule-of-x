Other modeling choices to note:
- F_A/(v T_A) is the straight-line charge of the spec; with discounting replace 1/T_A by the capital recovery factor r/(1 - exp(-rT_A)) (theory_ext does this). Every result holds with either.
- Duplication premium omega_par C_0 is added on top of the legacy cost on the unmigrated share, as the spec says (an alternative is max(1 - varrho, omega_par) C_0).
- Rollback: a failure is detected during the parallel run at rate 1/T_det; a detected failure is abandoned at T_par with no stranded costs; an undetected one is cut over and then rolled back at loss L_roll (valued at T_par). The spec's p_fail is p_fail = (1 - varpi_p) exp(-T_par/T_det). The spec does not say what drives p_fail; without a detection technology there is no interior optimal parallel run.
- J-curve productivity dip is a lump C^J at date 0 (spec lists it among one-time costs).
- Growth activities: growth spend buys a fixed bundle, so a proportional saving delta_sigma on the bundle maps to lambda (1 - delta_sigma)^(-alpha).

## 4. Formulas the engine must implement

Units: money in dollars per year unless "per unit"; volumes in units of output per year; hours in hours; rates per year; probabilities in [0,1]. All formulas are verified in `code/verify_part2_core.py`, whose functions `review`, `quality_cost`, `crossover_price`, `Wp`, `transition_npv`, `annual_dm`, `pilot_value`, `std_normal_loss`, `partI`, `gordon_root` are reference implementations.

### 4.1 Unit costs (per unit, $)
Inputs per activity j: v (units/yr), t (h/unit), w (loaded $/h), t_U (h/unit), t_R (h/unit), p_O, kappa_O, zeta_O ($/unit), n_U, n (inference units/unit), pi ($/inference unit), F_A ($), T_A (yr), K(x) ($ per unit/yr of capacity), delta_K (/yr), r (/yr), L_N ($/unit), feasibility flags.
- c(H) = w t
- c(O) = p_O + kappa_O w t + zeta_O
- c(U) = w t_U + e_U L + pi n_U  (e_U: added error rate of augmented work; 0 by default; positive for decision tasks outside the frontier)
- c(A) = pi n + cQ + F_A a / v, where a = 1/T_A (straight line) or r/(1 - exp(-r T_A)) (discounted)
- c(N) = L_N
- add (r + delta_K) K(x) to every mode (full cost; use for mode choice)
- best alternative cbar = min over feasible x != A; pre-AI cost c_pre = min over feasible {H, O, N}

### 4.2 Review share and quality cost (Prop prop:tasks-review)
Inputs: e (raw AI error rate, from readiness), L ($ mean loss per undetected error), w t_R ($ per review), d (detection rate of review; default from data/tasks/params_reliability.yaml review.catch_rate_ordinary 0.65 [0.45, 0.85], or catch_rate_hallucination 0.4 [0.2, 0.6] for confident AI errors), qbar, ximin.
- feasibility: A is infeasible if d < 1 - (1 - qbar)/e, i.e. e (1 - d) > 1 - qbar (no review share meets the target); with e(iota) decreasing this is a readiness floor iota_min where e(iota)(1 - d) = 1 - qbar
- xi_E = exp(-w t_R/(d e L)); xi_R = (1 - (1 - qbar)/e)/d; xi* = min(1, max(xi_E, xi_R, ximin))
- cQ(xi) = w t_R xi + e L [1 - d xi (1 + ln(1/xi))]  ($/unit); cQ = cQ(xi*); cQ(0) = e L
- residual error eps = e (1 - d xi*); step reliability q(A) = 1 - eps
- readiness link: e(iota) = e1 + (e0 - e1)(1 - iota) (default; any decreasing form works)

### 4.3 Activity breakpoints (Props modes, augment, breakpoints)
- crossover price pi* = min over feasible x != A of (c0(x) - c0(A))/(n - n(x)), with c0 the non-inference part; automate iff pi <= pi*
- volume threshold v* = F_A a / (cbar - cvar), cvar = pi n + cQ + (r+delta_K)K(A); automate iff cbar > cvar and v >= v*
- reliability threshold e*: root of cQ(e) = cbar - pi n - F_A a/v - (r+delta_K)K(A) (bisection on (0,1]); automate iff e <= e*
- readiness threshold iota*: root of c(A; iota) = cbar (bisection, on the feasible readiness range only); iota* = max(iota_min, root), with iota_min including the detection floor of 4.2
- decision-task dominance flag (Prop augment(d)): if t_R = t_U and (e_U - (1 - d) e) L >= pi (n - n_U) + F_A a/v + (r+delta_K)(K(A) - K(U)), drop U from the frontier
- report each distance: pi/pi* - 1, v/v* - 1, e/e* - 1, iota - iota*; and in posterior sd units (4.9)

### 4.4 Automation curve and inference demand (Prop prop:tasks-curve)
- S_A(pi) = sum_j E_j 1{pi <= pi*_j} / sum_j E_j with E_j = v_j w_j t_j
- inference demand N(pi) = sum_j v_j n_j(x*_j(pi)); savings W(pi) = sum_j v_j (c_pre_j - c*_j(pi))
- date of crossover with pi(t) = pi0 exp(-delta_pi t): t*_j = ln(pi0/pi*_j)/delta_pi (0 if already crossed; never if pi*_j <= 0)

### 4.5 Vendor window (Prop prop:tasks-window)
Inputs: c_VH, c_V0 (vendor human and non-inference AI cost, $/unit), ups_O (markup).
- vendor price p_O(pi) = (1 + ups_O) min(c_VH, pi n + c_V0); vendor switch pi_V = (c_VH - c_V0)/n
- D(pi) = c(O; pi) - c(A; pi); window nonempty iff D(pi_V) >= 0
- pi+ = [(1+ups_O) c_VH + kappa_O c(H) + zeta_O - c0(A)]/n
- D(0) = (1+ups_O) c_V0 + kappa_O c(H) + zeta_O - c0(A); pi- = 0 if D(0) >= 0, else -D(0)/(ups_O n) (empty window if ups_O = 0)
- window length (yr) = ln(pi+/pi-)/delta_pi
- make-or-buy volume v_MB = F_A a / [(1+ups_O) c_V0 + kappa_O c(H) + zeta_O - cQ - (r+delta_K)K(A)] if the bracket B > 0, else infinity; dv_MB/dkappa_O = -v_MB c(H)/B (AI that lowers coordination raises v_MB), dv_MB/dF_A = v_MB/F_A; report both sensitivities
- vendor price for residual work: allow p_O to rise with the difficulty of the units still outsourced (demirci2025who, hui2024short); default: no adjustment

### 4.6 Process value (Assumption ass:tasks-process, Props complement, aon, integration)
Inputs per process: activities with c_M = cbar, c_A; edges with v_e and eta(M,M), eta(A,M), eta(M,A), eta(A,A; iota) ($/unit); v_p; L_p ($ per failed output unit); q(M) per step; q(A) = 1 - eps; Xi_p ($/yr); critical path flags.
- W(Z) = sum_{j in Z} v_j (c_M - c_A) + sum_e v_e [eta(M,M) - eta(y_i, y_j)] + v_p L_p [Q(Z) - Q(empty)] + Xi_p [1{crit subset of Z} - 1{crit empty}], Q(Z) = prod_j q_j(y_j)
- optimal Z: enumerate all subsets if J <= 15 (2^15 = 32,768); otherwise local search from empty and full sets (the objective is supermodular, so a min-cut/submodular-minimization solver is exact; enumeration suffices in practice)
- dividends of full integration: unit = sum v_j (c_M - c_A); coordination = sum v_e [eta(M,M) - eta(A,A)]; reliability = v_p L_p [Q(all) - Q(empty)]; overhead = Xi_p
- integration premium over piecemeal = W(all) - sum_j W({j})
- integration constant h_p = min over proper nonempty Z of [(|Z|/J) sum_e v_e eta^x_e - sum_{e in Z} v_e eta^x_e] J/(|Z|(J-|Z|)); all-or-nothing certified if max_j W({j}) - min_j W({j}) <= h_p + Xi_p/(J-1) (report as a flag; the enumeration is authoritative)
- O-ring tolerance: per-step error <= 1 - qbar_p^(1/J); with step-specific errors use sum_k -ln(1 - eps_k) <= -ln qbar_p, and let eps_k rise with position for long single-agent chains (sinha2025illusion)

### 4.7 Readiness (Lemma lem:tasks-stp, Prop prop:tasks-readiness)
- straight-through rate: STP in [prod(1 - xi_j), min(1 - xi_j)]; use min when stakes are common along the process (invoice amount), product when independent
- process threshold iota*_p: bisection on W(all; iota) = 0 with every step's e, xi*, eps, c_A and eta(A,A) evaluated at iota; iota*_p = max(max_j iota_min_j, root)
- big push: invest iff max over iota >= iota*_p of [W(all; iota)/r - (I_p(iota) - I_p(iota0))] > 0; partial investment below iota*_p has zero value (default I_p convex, e.g. quadratic; data agent to supply)

### 4.8 Capital (Prop prop:tasks-capital)
- value test of a switch: NPV = [Dc - (r + delta_K) DK] * PV(v), PV(v) = v/r (constant) or v0/(r - g) (growth g < r)
- steady-state cash margin change = v [Dc - (g + delta_K) DK]/S; GAAP = v [Dc - delta_K DK]/S
- Part I mapping: Delta a = -v Dc/S, Delta k = v DK/S, Delta R* = -Delta a - (g* + delta_K) Delta k; m0 = gamma - a - delta_K k
- flag projects in the bands (g+delta_K)DK < Dc < (r+delta_K)DK (cash-positive, value-negative) and the reverse

### 4.9 Transition, success, pilot (Assumption ass:tasks-transition; Lemma lem:tasks-success; Props transition, scorepath, pilot)
Inputs: C_0 (legacy cost, $/yr), W (full-realization cash saving, $/yr, excluding amortized build), F ($, builds plus readiness investment), I = sum v_j DK_j ($), C_J ($), T_par (yr), ramp shape rhohat with mean rhobar (linear: 0.5), omega_par, nu_rec, E_p ($/yr in-house labor-equivalent spend), C_dup ($/yr), C_disp ($/yr displaced wage bill), u_d, T_sev (yr of wages), C_brk ($), C_wo ($, non-cash), varpi_p, bbar_p, T_det (yr), L_roll ($), T_h (yr), r.
- C_par = omega_par C_0 + nu_rec E_p + C_dup; C_str = (1 - u_d) T_sev C_disp + C_brk
- p_u = exp(-T_par/T_det); A_r(T) = (1 - exp(-rT))/r
- S_r = integral_0^T_par exp(-rt) rhohat(t/T_par) dt + [exp(-r T_par) - exp(-r T_h)]/r
- NPV = -(F + I + C_J) - C_par A_r(T_par) + varpi_p bbar_p W S_r - exp(-r T_par) {[varpi_p + (1 - varpi_p) p_u] C_str + (1 - varpi_p) p_u L_roll}
- minimum horizon (undiscounted) T_h* = (1 - rhobar) T_par + {F + I + C_J + C_par T_par + [varpi_p + (1-varpi_p)p_u] C_str + (1-varpi_p) p_u L_roll}/(varpi_p bbar_p W)
- payback (certain success): t_pay = (F + I + C_J + C_str)/W + T_par (1 - rhobar + C_par/W)
- optimal parallel run (undiscounted): chat = C_par + varpi_p bbar_p W (1 - rhobar); R = (1 - varpi_p)(C_str + L_roll); T_par* = T_det ln[R/(T_det chat)] if R > T_det chat, else 0; residual undetected-failure probability = T_det chat/(C_str + L_roll). With discounting, maximize NPV(T_par) numerically (bounded scalar search); the example differs by 0.01 yr.
- capability feasibility (theory_ext block): carry both reliability forms, logistic chi(q) = (q/(1-q))^eta_r and constant hazard chi(q) = 1/log2(1/q) (lags 2.32/4.93/7.70 vs 1.64/3.76/6.11 doublings at 80/95/99%), and domain-specific horizons (computer-use tasks 40-100x shorter, a 5.3-6.6 doubling offset, kwa2025how)
- benefit realization: bbar_p well below 1 for augmentation-led programs (humlum2025still); 0.85 is the automation-program example
- success probability: varpi_p = varpi0_p q(L/Phi); varpi0_p = varpi_c_p prod_{j in crit} varpi_pj; logit varpi_pj = a0 + a_iota iota_j + a_H ln(Hcal/dbar_j) - a_R 1{regulated}; logit varpi_c_p falls with exception share and ln(1 + affected FTE), rises with team experience share and sponsorship. All coefficients nonnegative and `assumed: true` unless the data agent sources them. q(L/Phi) comes from the theory_ext bandwidth block (1 if absent).
- Monte Carlo (for P10/P50/P90): success ~ Bernoulli(varpi_p); b | success ~ Beta with mean bbar_p (verify uses Beta(8 bbar, 8(1 - bbar))); detection time ~ Exp(mean T_det); apply the branch cash flows of the proof of prop:tasks-transition(a).
- score path, annual periods y = 1, 2, ... (success path, revenue S):
  - flow(t) = b W varrho(t) - C_par for t < T_par, b W after
  - cash: Delta R_y = [integral over year y of flow - (F + I + C_J) 1{y = 1} - C_str 1{T_par in year y}]/S
  - GAAP: Delta R_y = [integral of flow - C_J 1{y=1} - (C_str + C_wo) 1{T_par in year y} - (F/T_A) * (years of year y before T_A)]/S
  - closed form for year 1 when T_par <= 1 <= T_A, linear ramp: cash = -[F + I + C_J + C_str + C_par T_par - b W (1 - T_par/2)]/S; GAAP = cash + [F + I - F/T_A - C_wo]/S
- pilot (stage gate), inputs F_pil, T_pil, Y_s = NPV on success, Y_f = NPV on failure: d = exp(-r T_pil); gate varpi_gate = |Y_f|/(Y_s + |Y_f|); revealing pilot VP = d varpi_p Y_s - F_pil - max(0, varpi_p Y_s + (1 - varpi_p) Y_f); pilot iff F_pil/(d Y_s) < varpi_p < (|Y_f| - F_pil)/(|Y_f| + (1-d) Y_s); imperfect pilot with normal signal: VP = d shat L(|m|/shat) - (1-d) m^+ - F_pil with shat^2 the variance reduction.

### 4.10 Granularity (Prop prop:tasks-granularity)
For each activity (or process) with posterior mean m and sd s of the annual automation value Y (from imputation at the current tier):
- expected loss from deciding now: normal: s L(|m|/s) with L(u) = n(u) - u(1 - N(u)); distribution-free bound min(s/2, s^2/(4|m|))
- value of the next tier that cuts the variance to s'^2: shat L(|m|/shat), shat = sqrt(s^2 - s'^2); collect the tier for a cell iff the summed value exceeds its data cost
- spend-only data: zero decision value without fixed costs; with F_A > 0 and m_delta > 0, m_delta {E[(E - E*)^+] - (E[E] - E*)^+}, E* = F_A a/m_delta
- cell-level decision loss: min(sum Y^+, sum Y^-)
- report z = |m|/s per activity next to each breakpoint distance

### 4.12 Run costs, security and scope (Section 18; Props fullcost, buildbuy, security, secreview, ancscale)
Inputs per activity or process: delta_M (/yr, share of build), C_reval ($ per revalidation), T_up (yr between model upgrades or deprecations), N_j (integrations used), c_int ($/yr per integration), c_cpl ($/yr per coupled pair on an automated edge), exposure drivers (data class, write rights, reachable systems, external-input share) -> Omega_j(A), Omega_j(U), h_f (incidents/yr per unit exposure), h_u (incidents per unit of work per unit exposure), L_inc ($ per incident), C_s ($: spending that cuts the hazard by a factor e), risk-appetite exclusions (data classes; L_max), vendor platform terms (ups_B, F_V, C_reval_V, V_B, F_int, C_sw, T_c), review queue (nu deployments/yr, Phi_sec reviews/yr, p_sec $/yr per unit capacity, V_dep $, r_d /yr).
- annual run cost of an automated activity: delta_M F_A + C_reval / T_up (discounted: C_reval r/(exp(r T_up) - 1))
- technical debt of a process: C_td(Z) = c_int sum_{j in Z} N_j + c_cpl sum_{automated edges (i,j)} N_i N_j; equivalently the net edge premium eta^x_e - c_cpl N_i N_j / v_e
- incident cost without security: C_inc_j = Omega_j (h_f + h_u v_j) L_inc; process C_inc_p = sum_{j in Z} C_inc_j
- risk cost (exponential residual g(C) = exp(-C/C_s)): if C_inc_p <= C_s: C_sec* = 0, C_risk = C_inc_p; else C_sec* = C_s ln(C_inc_p/C_s), C_risk = C_s (1 + ln(C_inc_p/C_s)); general convex g: minimize C + g(C) C_inc_p numerically
- full unit cost (one-activity process): c(A) = pi n + cQ + (r+delta_K) K(A) + [F_A/T_A + delta_M F_A + C_reval/T_up + c_int N + C_risk(C_inc)]/v; same for U with F_U, K(U), Omega(U)
- in the process value W_p(Z): subtract sum_{j in Z}(delta_M F_A_j + C_reval_j/T_up) + C_td(Z) + C_risk(C_inc_p(Z))
- run-cost floor flag: automation can pay at some price only if c0(A) + c_anc(A) < cbar(0)
- volume-threshold factor from run costs: 1 + delta_M T_A + C_reval T_A/(T_up F_A)
- build vs buy: C_fix_build = F_A/T_A + delta_M F_A + C_reval/T_up + C_td; c_v = (1+ups_B)[pi n + (F_V (1/T_A + delta_M) + C_reval_V/T_up)/V_B]; C_fix_buy = F_int/T_A + C_lock; build iff v >= (C_fix_build - C_fix_buy)/(c_v - pi n); break-even lock-in C_lock* = C_fix_build - F_int/T_A - v (c_v - pi n); cap C_lock <= C_sw/T_c
- scope: exclude if data class excluded or L_inc > L_max; else automate j only if its savings exceed C_risk(C_inc_p(Z + j)) - C_risk(C_inc_p(Z)); report activities excluded from A but in scope for U
- security review: E[T_sec] = 1/(Phi_sec - nu); value lost per deployment V_dep r_d/(Phi_sec - nu + r_d); per year D = nu V_dep r_d/(Phi_sec - nu + r_d); marginal value of capacity nu V_dep r_d/(Phi_sec - nu + r_d)^2; optimal Phi* = nu - r_d + sqrt(nu V_dep r_d/p_sec); pace cap Phi_sec deployments/yr; with the decision gate: retained share exp(-r_d l_dec)(Phi_sec - nu)/(Phi_sec - nu + r_d)
- scaling report: classify each ancillary line as firm-fixed, per-process or per-unit; when the data tier pools P processes, add the understatement (P - 1) phi_bar, the Jensen gap (c/2) P Var(N) when integration counts are imputed at the mean, and the security pooling gap sum C_risk(C_inc_p) - C_risk(sum C_inc_p)

## 5. Where the spec is wrong or underdetermined

1. **Reserved symbols.** Sections 3, 4, 13 and 14 reuse reserved or Part I symbols: mu, psi_A/psi_min, beta_U, rbar/r_j, rho_d, s_w, S_p, pi_p (vs the inference price pi; now varpi_p), eta (Part I's eta = (1+g)/(1+r)), iota (Part I's Table tab:ai-map uses iota for compute intensity in c_c = p_c iota/p; a one-off, but readers will see it). Renames are in Section 2.
2. **Section 3, c_A.** psi_A and eps_A are not independent: the undetected rate is e(1 - xi), and with stakes heterogeneity the expected loss is below eps L. The spec does not say how psi_A depends on iota and reliability; Prop prop:tasks-review derives it.
3. **Section 3(a), "the curve shifts right".** Direction depends on the axis. Precisely: S_A is lower at every price and each crossover date is later by ln(pi*/pi*(O))/delta_pi.
4. **Section 3(b), all-or-nothing.** Supermodularity alone does not give all-or-nothing; it needs the dispersion condition of Prop prop:tasks-aon, which is sharp for chains and tightens like 1/(J-1). Long chains peel at their ends. Step changes of whole-process size (Section 8 item 5) need a process-level benefit released only by end-to-end automation (the overhead Xi_p, or latency) or strong handoff premia; otherwise partial automation of sub-chains is generic.
5. **Section 4, "below iota*, only augmentation pays".** True only if augmentation beats in-house and outsourcing for each activity and all-or-nothing holds; otherwise the low-readiness mode can be outsourcing (as for two steps of the running example).
6. **Section 4, iota_p = min or product.** Both are correct, as the two extremes of stakes dependence along the process (Lemma lem:tasks-stp); the engine needs a flag for common versus independent stakes.
7. **Section 8 item 2.** v* = F_A/[T_A(c_min - c_A^var)] holds only if the alternatives have no fixed cost, and c_min must include augmentation, not only H and O.
8. **Section 8 item 3.** With an oversight floor the review share falls to xi_min, not 0, and the threshold variable is the raw error rate e (the residual eps is chosen).
9. **Section 13.1.** The value test is Dc > (r + delta_K) DK for every growth path; growth does not enter the value test. "g K" belongs to the steady-state cash score only (Prop prop:tasks-capital). Part I's Cor substitution (g*) compares steady states and omits the retrofit of existing capacity; including it raises the hurdle to r (checked numerically, check 20f).
10. **Section 13.2.** "Reverts and bears the parallel costs again" does not determine an optimal parallel run; the trade-off requires a detection technology (T_det). The data agent should supply T_det priors. The duplication premium is ambiguous (additive or a floor on legacy capacity); I used additive, per the text.
11. **Section 14.** The capability margin H kappa_ctx - d chi is a difference in hours, not scale-free; the logit uses ln(Hcal/dbar). The success probability of a process should multiply along the critical path (Lemma lem:tasks-success), which makes complexity (number of activities) enter as a sum of hazards rather than as a separate driver.
12. **Spec Section 2.** O*NET has 2,087 DWAs (release 30.2), per notes/ref_verification_part2.md; the fragment says so.

13. **Section 18.** mu_m, e_j and s_sec clash with reserved or existing symbols (renamed delta_M, Omega_j, C^sec_p). Technical debt "with integration count and coupling" is unspecified; modeled as an edge term so it nets against the integration premium (it weakens all-or-nothing). Gordon and Loeb (2002) is now cited (gordon2002economics) in Prop prop:tasks-security(b) and its intuition, with the caveat that the 1/e bound holds for their two classes of breach functions (the exponential residual here has the form of their second class) and fails for others (hausken2006returns); the %CITE comment is removed.
